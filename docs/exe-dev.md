## 离线验证与边界

exe-dev 有 3 项确定性检查：

1. 独立文件白名单、frontmatter、MIT 一致性、本地引用与片段锚点、来源摘要格式。
2. 复制到中文空格目录后引用仍完整，不依赖外层仓库、脚本或 npm 包。
3. 唯一流程／边界锚点、参考中无第二套编号执行步骤、官方来源入口、README 安装入口与 Git 白名单。

不再用“某句安全话必须原样存在”判定行为正确；结构检查不能替代对实际含义的审查。它们不证明 Agent 触发率、流程遵循、攻防或平台功能。未执行 SSH、VM 操作、凭证生成、模型请求或真实收费接口，未完成 Windows／宿主真实加载验收。仓库整体测试基线见 [status.md](status.md)。

### 静态流程走查用例

| 用户意图与授权 | 预期分支／停止点 | 复核结果 |
| --- | --- | --- |
| “只告诉我如何让朋友访问一台 VM” | 咨询 → sharing → 逐项解释 Web／Root／团队及来源后结束；远程命令不可达 | 主流程第 2 步咨询出口覆盖 |
| “可以只读查这台 VM，公网未授权但 localhost 健康，不要修改” | 只读排障 → operations + proxy-auth → 获准查询后给证据、原因／未知项及修复建议，结束 | 独立只读出口，不能进入第 3 步 |
| “已确认只给这个邮箱指定 VM 的 Web 权限” | 变更 → sharing → 对照已有授权列计划，执行后按接收者×权限回查；无需重复询问已覆盖动作 | 第 3 步授权匹配及第 4 步逐项验收覆盖 |
| 创建或购买请求超时，结果未知 | 标记未知，暂停后续动作，先查状态，再按授权决定继续／回滚；不重复提交 | 第 3 步停止状态与 boundaries 重提限制覆盖 |
| 咨询两 VM 分发敏感原文，追问“用户拿到后能保证不外传吗” | secret-delivery → 说明接收者可保存、B 被攻破仍可截获；结论和建议后结束 | 能力边界覆盖，非远程实现 |
| “替我把本机 Key 配到平台 integration” | 按凭据硬边界只提供用户自行配置的方法；不读取或上传真实值 | boundaries 覆盖，主题参考引用同一规则 |
| “帮我看看模型是否支持，空 messages 应该免费吧” | billing-and-llm → 清单／文档取证；真实模型调用需费用授权，咨询阶段不发送探测 | 模型发现与调用分别处理 |

以上为人工静态审查，不是独立模型执行结果。No-op 候选可静态裁剪，但是否真正改变模型行为，需要另行授权的场景对照评测，不能由通过结构测试推导。
