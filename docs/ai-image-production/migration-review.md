# AI 图片技能特有的迁移问题

通用 fal 适配、未知提交及独立分发要求引用[游戏素材迁移审查](../game-asset-production/migration-review.md)，这里仅保留本技能的新增问题。以下为静态审查，不是已完成修复。

## 路由与授权差异

| 影响来源 | 本技能特有问题 |
| --- | --- |
| 主文档、生成参考 | 默认依赖 HubKKK，但新项目只有 [HubKKK 资料](../hubkkk/README.md)，没有执行技能；不能直接迁入后声称可用 |
| `element-extraction.md` | GPT Image 1.5 编辑备选不在新 fal 清单；公开 URL 要求也不能被解释为自动授权公开上传本地图 |
| 透明能力描述 | 2026-08-25 的失败样本被写成 GPT Image 2 不支持透明；新本地[模型说明](../../skills/fal-ai/references/images.md)已有 transparent 参数。样本失败不证明永久不支持，参数存在也不证明质量合格 |
| 默认模型跟随 | 跟随 HubKKK 默认但不传模型可能随下游变化改变行为；需要记录实际解析模型，不静默替换 |
| 失败回退 | 数量失败要求逐次重生成确认，透明失败却写成直接色底生成＋去背景；需要统一额外请求与费用边界 |
| 偏好与调用路径 | 个人路径绑定原宿主布局，示例混用 Skill 相对入口和仓库根路径；需适配任务 cwd，不能复制用户配置 |

本次未核对最新 API 或生成质量，也没有修改旧默认值。

## 评测定义与正文冲突

`evals/evals.json` 的 14 个案例中：

- **用例 4** 要求 Key Color 优先且不做生成后 Alpha 探测，与正文透明直出优先相反。
- **用例 6** 请求“不要重画”，预期却要求 AI 生成新的透明元素，可能把违反用户要求的行为判对。
- **用例 1、13、14 等**仍围绕旧去背景流程，需要与现行任务分支重新对齐。

先修预期再评测，不让旧断言反过来覆盖用户限制；此处只记录冲突，未改原案例或复制任务路径。

## 像素与布局差异

| 影响文件 | 需要补的契约／测试 |
| --- | --- |
| `split-grid-assets.mjs`、`grid-generation.md` | 文档允许空 cell，脚本却要求全部 `rows × cols` 格有名称和内容；需显式有效格映射，不能生成多余对象填格 |
| `split-grid-assets.mjs`、`grid-assets.md` | 报告边界用 `floor(col × width / cols)`，像素归属用 `floor(x × cols / width)`。宽 401、2 列时，报告右格从 x=200 开始，归属仍把该像素分到左格；需统一分区并补贴边样本 |
| `image-utils.mjs`、透明／组件文档 | 校正 [Alpha 字段与阈值语义](alpha-and-grid.md#阈值和-alpha-字段)，补全幅半透明、合法低 Alpha 及粒子归属反例 |
| `trim-transparent.mjs`、编码与预览 | 将 padding、WebP 有损／无损、插值和用途标记按[工具差异](tools.md)明确，而非照搬游戏实现的保证 |

分区例子可由公式直接核对；不代表实际生成图片已经复测。写入保护差异统一留在[工具说明](tools.md#与游戏工具不同的写入保护)，不再重复通用安全清单。
