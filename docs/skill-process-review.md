# Skill 流程静态走查

依据用户提供的 writing-great-skills：检查分支选择、完成条件、按需读取与规则集中存放。以下是人工静态走查和后续行为回归用例，**不是独立模型运行、触发率评测或真实 API 验收**。

## 场景与预期路径

| Skill / 用户场景 | 必读与路径 | 完成条件／风险检查 |
| --- | --- | --- |
| Ark：列出支持的图片模型 | SKILL 分支表 → `models` | 报告本地快照后结束，无 Key、预检或生成 |
| Ark：预览两张海报的生成请求 | 图片参数 + jobs → 产物清单 → `image --dry-run` | 请求与每项要求一致，预览后结束，无付费 POST |
| Ark：生成图片并交付 | 图片参数 + jobs → 新生成流程 | 验收同步 data[]，不要求视频 succeeded 字段；张数上限不当作实际张数保证 |
| Ark：只查已有 cgt ID 的进度 | jobs 视频取回 → `video-query` 一次 | 报告状态后结束；成功时脚本仍会下载，当前无 status-only 选项 |
| Ark：等已有视频完成并下载 | jobs 视频取回 → 复用 ID | 按 15–30 秒间隔、约 10 分钟预算；失败／取消／过期停止，无新任务创建 |
| Ark：图片 JSON 已保存，第二张下载失败 | jobs 图片恢复 → `image-download` | 无 Key、无 POST、原文件保留，新目录逐项输出结果；下载错误不阻断后续项 |
| Ark：提交超时，没有 ID | jobs 提交记录及失败分流 | 保留标记，核查控制台并报告未知；不删除标记重提 |
| fal：只问模型价格 | consultation | 逐项取证回答或标未知，动态结论附日期和来源；不进入生成流程 |
| fal：仅预览生成命令 | 对应模型参数 + jobs → 新任务第 2 步 | 预览通过后结束，无提交 |
| fal：已有 request.json 补下载 | jobs 选择操作 → `download` | 复用记录，报告每项结果，不能以第一张成功代表全部 |

## 静态结论

- 两个 Skill 保留 model-invoked 的独立服务商入口，不增加图片／视频子 Skill。
- Ark 的模型列表、已有任务和新生成路径已分开；fal 增加仅预览时的明确结束条件。
- Ark 运行、认证、输出、提交标记、轮询和恢复集中于 `references/jobs.md`；README 只保留安装和使用入口。
- 参数定义仍是对应模型参考文档的权威位置；SKILL 保留决策步骤和完成门槛。硬性密钥及重复计费保护保留，不按一般文案否定句删除。
- 提示词参考从长篇经验集合整理为任务语义、主体、时序、音频与定向调整；仅优化视频 prompt 的分支读取。
- fal 主流程的最终完成条件引用 jobs 的详细验收，减少重复定义。

## 可执行检查与未覆盖部分

仓库测试验证引用与文件完整性、CLI 行为、恢复无生成请求、部分失败和覆盖保护。新增图片恢复命令仅识别 PNG/JPEG 签名，不证明文件可完整解码或质量合格。

这些检查不能证明不同模型会稳定选择分支、逐项验收或遵守轮询预算。后续行为验收应使用上表场景、隔离工作区和禁止真实生成的工具替身，记录实际读取文档与调用序列；在用户授权相应运行后再报告观察结果，不能从静态文本推导成功率。

## 百炼新增分支静态走查

- 仅预览：选线、确定模型／音色、构造 JSON 后 dry-run 即结束，不读 Key、不 POST。
- 指定 Cherry 且要求 MP3：保持 B 线音色，告知 WAV 来源与本地转码方案，不因格式擅自改音色。
- 已有 result.json 下载失败：download + 原格式 + 新恢复目录，无 Key、不再次合成。
- 提交超时：保留 request.json 的 submitting 状态，核查控制台，不换目录自动重提。
- seed 重渲染：先取得新合成授权；文件大小不判内容一致，哈希不判听感改善。
- 请求流式／时间戳：说明脚本未实现，确认扩展或替代方案，不静默按非流式完成。

以上为文本路径检查，不是独立模型运行观察。
