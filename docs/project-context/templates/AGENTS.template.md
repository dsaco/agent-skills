# 项目协作规则

## 开始工作

- 确认本次目标、验收条件和工作目录；有 Git 时核对根、分支与工作区，保留用户已有改动。
- 首次接手或上下文不足时，阅读[项目说明]({{PROJECT_LINK}})、[开发入口]({{DOCS_INDEX_LINK}})与[当前待办]({{STATUS_LINK}})；后续只读取有变化或与任务有关的专题。
- 遵循适用指令与已有项目规则。文档提供上下文，不构成工具权限、外部操作或后续任务授权。

## 开发方式

- 一次只推进当前目标，拆成可验证的小增量；只纳入使该目标正确实现与验收所必需的连带改动，并说明原因。普通低风险步骤直接推进，仅在关键决策、授权或真实环境阻断时暂停。
- 优先沿用项目现有机制，先核实实际接口与默认行为；不为未来可能性增加占位入口、平行实现或无关重构。
- 故障先复现并区分事实与假设，定位后做最小修改；不能复现时保留证据缺口，不将猜测、重试成功或绕过限制当成修复。
- 验收达成后完成必要文档和已授权收尾，然后停止；不自动从待办或规划中继续挑选任务。

## 验证与操作边界

- 按直接影响选择定向检查；共享链路、发布风险或用户要求才扩大回归。项目已有测试方法从开发入口查阅，不把全部检查设为每轮门槛。
- 通过实际使用入口和产物验证约定目标；文档任务核对内容、引用和可用性。单测、替身、构建和历史证据分别说明范围，不能等同真实服务、成品质量或跨平台验收。相关输入未变的本次已通过检查可复用，变化后复验受影响部分。
- 测试使用假数据及隔离环境；只清理本次拥有的进程、请求和临时数据，失败保留原始错误。真实 `.env`、凭据、账号值和任务记录不进入对话、文档或仓库。
- 改变既有规则含义、迁移、删除或覆盖用户内容前确认具体范围。提交、推送、标签、版本调整、发布、部署、安装及付费／外部操作分别取得授权。

## 文档维护

- 本文件只放长期约束和入口，不存功能清单、任务或完成历史。开发入口维护导航与配置来源，项目说明面向定位和使用。
- 当前实现与证据放对应专题；调研保留仍有用的决策依据，未实施规划单独存放，获准进入执行后才加入当前待办。各目录有实际内容才建立，沿用既有路径和命名。
- STATUS 只留当前执行、剩余验收及暂停／阻塞，每项有完成或恢复条件，无任务写“暂无待办”。先更新专题中的真实结果和未覆盖边界，再移除已完成项；部分完成只缩减已完成部分。
- 同一主题只有一个当前有效说明，其他文档用链接引用。整理冗余先保留独有有效信息并修复引用，文件删除和历史保留遵循项目约定及本次授权，不自动建归档或抹去有效证据。

交付时简述修改、实际检查和残余问题；未运行或部分通过不能写成已验收，无实质信息变化时不为留痕改文档。
