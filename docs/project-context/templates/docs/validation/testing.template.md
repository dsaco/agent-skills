# 测试方法与证据边界

按[开发入口]({{DEVELOPMENT_LINK}})选择相关专题和真实命令；没有程序运行环境的项目，以文档、链接和交付物检查替代不适用环节。本文不新增工具、权限或付费调用授权。

## 选择检查

- 局部改动做定向检查；影响共享链路、发布或用户明确要求时扩大回归，而非每轮运行全部脚本。
- 检查前确认对象、前置条件与副作用，代码和对应产物一致。本次已经通过且输入、产物、环境未变的结果可以复用；发生相关变化后只重建并复验受影响部分。
- 真实账户、安装依赖、外部下载、付费服务或生产环境测试另需授权，不能因为“验收需要”自行执行。

## 证据范围

- 单元／替身检查证明其覆盖的逻辑；本机集成证明接线，不证明真实账户、模型质量或服务可用性。
- 源码构建、分发包、不同系统与架构分别说明；不得用一个平台代替另一个平台的验收。
- 静态说明、测试脚本、截图文件存在不等于本次已运行；视觉结果应实际查看，模拟交互不等于原生设备实测。
- 记录必要的对象、版本／环境与结论，保留未覆盖范围；不把历史通过改写成本次重测，也不逐轮累积通过数量和耗时。

## 故障到验收

1. 明确用户动作、预期产物和状态，以及本次相关的失败／取消标准。
2. 尽可能在隔离环境重现，保留与故障相关的路径、缓存、首次准备和并发条件；区分首次使用与准备后的测试。
3. 分开列事实、原因假设和证据缺口；定位后做最小修改。不能复现时保留边界，不用延长超时、反复重试或放宽权限代替定位。
4. 用相同条件的修改前后对照做定向验证；无法对照时明确限制，核对真实错误、退出状态与产物，不从一行成功提示推导完成。
5. 从约定的正式使用入口验收；CLI 经 CLI、服务经目标服务接口、界面经实际界面、文档经交付结构。单独探针只作为局部证据。

文档收尾顺序与停止点见 AGENTS；专题记录结果和边界，当前待办只保留未完成部分。

## 隔离与清理

使用假数据、临时工作目录和本机替身，不复用真实账户、登录态或密钥。需要隔离哪些用户目录与系统缓存取决于实际工具，不能仅凭设置一个环境变量宣称完整隔离。

成功、失败和超时都清理本次拥有的进程、请求与临时业务数据，保留原始错误和失败退出状态。按已记录的对象身份清理，不宽泛结束进程、不关闭用户日常应用、不删除既有数据；需要保留的非敏感证据遵循项目现有约定。
