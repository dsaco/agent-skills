# 验证与场景

这里只修订技能草稿与模板，未安装、应用到项目或运行独立模型对照。参考项目的流程约定与实际行为效果是两回事，静态阅读和模板渲染不能证明 Agent 会正确遵循。

## 人工静态走查

以下沿正文核对分支、停止点与预期结果，不是模型执行成绩。

| 场景 | 预期行为 | 静态依据 |
| --- | --- | --- |
| 空项目只给名称和目标 | 补足规则、说明、导航、待办职责；未知待确认，不铺空目录 | 初始化分支与按需建档 |
| 已有 README、AGENTS、大小写不同的状态路径及专题 | 原样保留既有规则，按职责沿用，不造第二份导航或进度 | 第 1、2 步路径与职责映射 |
| 功能已实现、入口关闭、离线通过 | 专题写适用维度，STATUS 只列开放条件和待验收动作 | 第 3 步专题／待办分工 |
| 本次约定验收全部满足 | 先更新专题，再移除当前条目；清理已授权内容后停止 | 第 3、4 步与 AGENTS 收尾 |
| 部分实现、缺平台或真实服务验证 | 已知结果保留专题，余项留在剩余验收；不自动触发真实调用 | 状态转换与验证边界 |
| 无当前任务 | STATUS 写“暂无待办”，不补完成历史或人为任务 | 待办模板与职责参考 |
| 未来方案仅获准记录 | 放规划／既有方案文档；未进入执行不加入当前任务 | 分工与开发入口模板 |
| 故障未复现或用户已暂停 | 保留证据缺口、恢复条件，不认定修复或继续重试 | AGENTS 与测试方法模板 |
| 局部变更、共享链路变更、只整理文档 | 检查范围按影响区分；不运行全部脚本，不用文档测试冒充产品验收 | 测试方法模板 |
| 只创建 AGENTS、只咨询、无 Git 的文档项目 | 各按本次分支裁剪产物和链接；无需初始化 Git、生成测试架构 | 分支与条件化模板规则 |
| 来源有“删除旧文档、不建归档”约定，但目标有审计留存 | 先保留有效信息，遵循目标约定与授权；不照搬删除策略 | 参考取舍与保留策略 |
| 文档冲突、越界链接或已有 ADR 自定义约定 | 保留来源、暂停受影响写入，沿用编号与状态，不重置体系 | 第 1、3、4 步边界 |

## 确定性检查

本地检查限于：文件集合与元数据、Markdown／引用、模板占位符登记与隔离渲染、来源摘要、敏感模式和改动边界。

渲染场景使用合成资料，不调用模型：

- 默认开发项目：采用开发入口、STATUS、单个专题及共用测试方法，核对链接与占位符。
- 已有 README、小写状态与 docs/README 导航：使用不同路径填充模板，检查不生成大小写重复文件；保留夹具中的原规则与说明。
- 没有剩余任务：按模板说明裁掉空区域，状态文件只保留必要说明和“暂无待办”。
- 单文件／纯文档：裁剪 AGENTS 中不存在的导航，不创建额外文件或程序测试配置。

本轮结构、引用、占位符与上述四个隔离渲染场景检查通过；来源摘要一致，变更范围仅在本草稿目录，当前项目规则与进度、参考项目及两个旧源项目均未改动。

渲染只证明模板可以被按规则组合，不测试 Agent 是否会自动作出正确选择。来源文档内容、参考仓库 Git 状态与目标非授权文件单独核对。

## 验证边界

- 未测试 Skill 安装、自动发现、AGENTS 自动加载或作用域；未迁入 `skills/`。
- 未做独立模型、触发率、连续多轮维护或复杂冲突行为评测。
- 本机模板检查不等于 Windows 或其他文件系统验收；只验证样本路径拼写与引用。
- 未执行参考项目的测试／构建，也未调用真实服务、读取 `.env` 或应用本模板。
- 本轮无运行代码变更，原技能测试套件不是此草稿的行为验收，不为文档改动重跑全套。

后续如获授权做行为评测，应重点检查“只推进当前目标、保留既有规则、先专题后待办、部分完成不夸大、收尾停止”，不以规定句子存在替代实际行为。
