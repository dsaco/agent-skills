# project-context · 项目上下文

从一次性项目初始化扩展为建立、维护和交接项目协作流程。参考用户指定项目的实际分工后，默认采用：**长期规则在 AGENTS，剩余工作在 STATUS，当前实现与证据在专题**。

当前仅保存技能草稿与模板，没有注册、安装或应用到本仓库。AGENTS 是文字指引，不是权限隔离或自动加载保证；宿主是否读取及如何处理作用域另行确认。

## 默认组织方式

下面是采用后可能形成的结构，**不是全部必建，也不是本仓库已采用的结构**：

```text
项目根目录/
├── AGENTS.md              # 长期规则和任务闭环
├── README.md              # 定位与使用；存在时优先沿用
└── docs/
    ├── development.md     # 开发与文档入口
    ├── STATUS.md          # 只列剩余工作，无任务写“暂无待办”
    ├── validation/        # 有真实内容才建立
    │   ├── testing.md     # 共有验证方法
    │   └── <topic>.md     # 当前实现、验证入口与证据边界
    ├── research/          # 仍指导决策的调研，按需
    └── plans/             # 未实施方案，按需
```

已有 `docs/README.md`、`status.md`、专题、设计或 ADR 体系直接沿用，不为默认命名迁移。项目说明缺失时才用 `docs/project.md` 模板补齐；没有程序执行需求时不机械生成测试方法。避免大小写双份文件、空目录和重复事实来源。

## 维护闭环

当前目标 → 明确验收 → 小步推进与定向验证 → 实际入口检查 → 更新专题 → 移除已完成待办 → 收尾停止。

无法定位、未验证或部分完成时，保留剩余工作、证据缺口和恢复条件；不将其标成已验收。未来规划不是当前任务，状态列表也不代表后续执行授权。

相较初稿，状态页不再保存“开发进展表／近期关键结果”，这些有效信息进入专题；默认导航改为开发入口，新增专题与测试方法模板。上述是文档设计，不是已经证明更有效的模型行为。

## 使用边界

- 模板是非活动文件；使用时由执行者替换 `{{...}}`、裁剪可选项并核对实际相对路径，不把本目录直接复制到项目根。
- 初始建档和后续更新都是最小整合，不覆盖已有规则；文件删除、迁移和历史保留按目标项目约定与授权处理。
- 没有执行参考项目的命令，没有复制其技术栈、UI 规范、账号配置或宿主能力要求。
- 当前仓库的实际 AGENTS、进度、Skill 白名单和原技能未改。转成可分发 Skill、应用到项目或做独立模型评测需另行授权。

本次原创草稿与模板按仓库 [MIT](../../LICENSE) 提供；参考模式不表示对来源项目或第三方材料重新授予许可。
