# 任务生命周期与旧实现审查

静态审阅对象为旧 `gpt-image-2.js`、`banana2.js`、`generate-image.js`、`shared.js`，未执行这些脚本。接口和参数在[模型快照](models-and-api.md)定义，本页不重复维护。

## 旧代码实际行为

| 分支 | 静态行为 |
| --- | --- |
| dry-run | 输出请求／恢复计划，在读取 API Key 之前结束，不联网或写生成文件 |
| 默认同步 | 创建任务 → 递归提取 task_id → 轮询 → 保存结果 JSON → 下载图片；创建响应和 ID 没有在轮询前落盘 |
| async | 创建返回非空 ID 后写 `<out>.json`，包括 payload 和提交响应；然后返回 |
| resume | 按 ID 查询，不重新 POST；仍需要 Key，终态成功后写 JSON 并下载 |
| 终态 | `is_final === true` 时以 `state === success` 判成功，其余为失败；中文展示字段不参与判断 |
| 默认等待 | 轮询间隔 10 秒、整体参数 600 秒；单次 fetch 使用 120 秒定时器，但拿到 Response 后清除，响应体读取不受该定时器完整覆盖 |
| 下载 | 递归收集 `url`／`result_url` 去重，顺序下载；多图用编号后缀；保留用户输出后缀，不转码 |

同步分支没有 ID 时会将创建响应直接作为最终结果处理。递归提取和 URL 收集未绑定固定响应 schema，可能选中非目标字段；不能把“找到了 URL”当生成成功证明。

## 文档矛盾与实现缺口

1. **默认模型矛盾**：旧官转参考写默认官转，实际 GPT 脚本默认普通模型，以源码为静态事实；远端模型是否对应预期仍需核实。
2. **未知提交缺少留据**：POST 超时／进程中断时可能没有 task_id；同步模式直到最终成功才保存 JSON，不能声称所有中断都可直接恢复。已有 ID 才能走 resume。
3. **覆盖与部分失败**：输出文件和 JSON 可被直接覆盖，下载失败可能留下不完整文件集；没有独立补下载清单、原子写入或逐图验收。
4. **媒体校验不足**：没有非空／格式／可解码检查，也不验证尺寸或 Alpha；扩展名可能与响应字节不符。
5. **响应与 URL 边界不足**：原始 payload／响应落盘，错误直接带响应文本；缺少系统脱敏。fetch 默认跟随重定向，参考 URL 与下载目标没有完整的凭据、来源及网段边界策略。
6. **参数隔离不完整**：官转模型的部分普通模型参数会被静默省略；`n` 无最大值，多图 URL 的公有可达性也未验证。
7. **模块与时间预算**：CommonJS `.js` 未在 Skill 根提供 package.json；整体轮询 deadline 不是严格的请求加读体总预算。跨宿主和跨平台未验收。

源代码未写应用层自动重提交循环，这一点不能推导成已有幂等保障；重新启动命令仍可能再次创建付费任务。

## 后续接入条件

若未来另行授权接入，应先解决：

- 提供方文档／许可／账户权限／价格核对；API label 与实际模型来源清晰区分。
- 参数白名单、模型隔离、URL 安全边界、私有素材授权和正确模块配置。
- 提交前后留据与结果未知状态；已有 ID 恢复仅查询／下载，不自动重新生成。
- 凭据与签名 URL 脱敏、重定向策略、请求及响应体超时、非空和格式验证、覆盖保护。
- 多图结果逐项成功／失败记录，下载失败从记录恢复；图片质量、Alpha 与尺寸另做内容验收。
- 假凭据和临时目录的离线测试，覆盖错误响应、部分下载、进程中断、未知提交和独立目录运行。

目前仅保留这些设计输入，没有在本项目添加新的模型调用、环境变量或运行入口。
