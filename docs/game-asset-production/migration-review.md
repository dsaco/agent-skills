# 迁移审查与验证边界

本次是文档整理，不是旧技能迁入或运行修复。以下发现来自静态阅读与来源文档对照；未调用模型、安装依赖、运行媒体处理或复现真实产物。

| 逐帧去背景 | `remove-background.js`，输出文件和 JSON 字段的旧约定 | [fal 去背景说明](../../skills/fal-ai/references/background.md)包含 Ideogram，但入口与[任务恢复协议](../../skills/fal-ai/references/jobs.md)不同 |
| 图生视频 | `image-to-video.js`，旧模型别名与任务处理 | 新 fal 是图片版，没有此入口；保留旧能力、补支持或更换服务需单独决定，不能静默降级 |
| 本地加工 | Node + ImageMagick、ffmpeg／ffprobe；可选 Python／Pillow | 本资料未迁入脚本或安装依赖，不能把源码存在当新仓库已经可用 |

原素材技能独立于 `ai-image-production`，不需要为迁移而强制绑定其流程、依赖目录或个人偏好。服务商协议由底层技能维护，素材层保存规格、路由和交付检查即可。

## 批处理不是通用自动生产

`produce-animal-batch.mjs` 固定了动物清单、朝左侧视、惊慌逃跑、特定插画风格和动画标识，默认打包尺寸为 200；可选复核还保留 80 像素循环与缩放假设。这些来自具体任务，不应当作所有游戏素材的默认要求。

另有执行边界：

- 默认步骤包含本地入库，分析后直接消费 `delivery.removalFramesSpec`，没有独立的选帧／视觉批准状态再进入付费与替换。部分警告只是记录，不阻断。
- 同名入库会先备份再替换，备份不等于获得覆盖授权；候选生产与正式资源替换应分为不同阶段。
- 多个步骤仅凭产物路径存在就跳过，清单、提示词、源图或参数变化可能没有使旧结果失效；“每步幂等”表述过强。
- 去背景子过程允许非零退出后继续解析，部分情况下若无结构化失败列表，失败没有被可靠升级；可选 Python 复核也未严格检查退出状态。未来应统一失败传播及整批退出状态。
- 成本使用固定的历史单价和覆盖式汇总，不等于实际账单或完整尝试历史；需要区分估算、提交数、成功数及未知结果。

建议将题材、动作、朝向、画风、尺寸、时间、锚点与入库要求移入显式任务清单，先保留专用脚本为待重写案例，不把它包装为通用自动流水线。

## 续跑、修复与写入保护

建议重点改造 `run-video-generation.mjs`、`remove-frames-background.mjs`、批处理及发布／重打包脚本：

- **未知提交**：提交标记只能证明本地流程走到某一步，不能证明已扣费或未受理。去背景中断／失败后再次执行未完成帧可能发起新请求；应先核查已有任务并区分查询、补下载和重新生成。
- **输入身份**：源视频或帧目录、选择帧集、模型、提示词与相关参数纳入身份；不因工作目录有旧抽帧就直接复用，也不把缺哈希旧账本当完整校验。
- **修复配方**：当前自动重修判断主要比较上下阈值，没有完整涵盖 floor、despill、defringe；修复直接改目标图，关闭选项不能保证恢复已损失颜色。应保留不可变模型原图，按配方派生修复结果。
- **覆盖与恢复**：本地发布的 `replace` 删除整个目标子目录再重建，不是原子替换；重打包备份可省略、固定工作子目录会被清理。应核对路径与符号链接、保护既有内容、明确备份／恢复并分离预检和写入。
- **认证与依赖**：视频与去背景的凭据读取优先级不同，前者还查用户目录配置；本地修复分支也要求 Key 和旧调用脚本。应统一最小读取范围，使纯本地处理不依赖真实认证。

这不是完整安全审计，也未实际触发上述失败。旧脚本未修改，记录改进点不等于保护已实现。

## 历史证据与保留价值

源 `validation-record.md` 主要记录 2026-09 的有限样本：Flare 透明静态生成与局部修订、参考驱动的图片帧表、视频交替步态、逐帧抠像、共享画布、编码和播放器问题。本次不复制项目成员、任务目录、原始媒体或账单。

值得保留的经验是：

- Alpha 最大值不到 255 不代表背景不透明；阈值变化需保护合法半透明内容。
- 首帧细节、方向与运动要求的冲突会影响视频结果，但少数样本不足以证明唯一因果或稳定成功率。
- 基本周期与倍周期、源帧号与输出索引要核对；共同坐标不能用逐帧紧裁替代。
- 黑白灰底、逐帧目检、真实速度播放与像素核验各自提供不同证据。
- lossless 编码、播放器无异常、局部本机通过都不能证明引擎可用、动作自然或跨平台验收。

来源目录当前定义 12 个静态处理测试、10 个帧处理测试及一份人工决策场景；未见覆盖全部视频提交、未知请求恢复、批处理与发布故障的同等测试集。历史通过记录不是本轮执行结果。

## 后续接入条件

正式迁入前应另行明确并验收：

- 底层 fal 图片／去背景适配和视频能力保留方案，用户选定模型不被静默替换。
- 通用规格与任务案例分离；选帧确认、批量成本范围、失败停止及正式替换授权。
- 提交留据、输入身份、纯本地修复、覆盖保护、退出状态和恢复流程的假数据离线测试。
- 依赖与最低运行时、独立目录运行、Mac／Windows 路径及权限、独立 README／LICENSE。
- 真实 API、媒体质量和引擎消费方单独验收，只有额外授权后才执行。

本次完成的是资料组织、引用／来源与改动边界检查；没有重跑旧技能测试，没有生成媒体或确认真实接口可用。
