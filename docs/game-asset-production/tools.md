# 旧工具清单

以下 12 个脚本只在**来源版本**中存在，本资料目录没有复制它们，也不提供可直接执行的命令。表中“不调用模型”仅表示该脚本的网络／模型职责，不表示没有本地写入、删除或资源成本。

## 能力与副作用

| 源 `scripts/` 文件 | 输入 → 输出 | 依赖与边界 |
| --- | --- | --- |
| `prepare-static-sheet.mjs` | 透明规则合图＋成员清单 → 独立图、预览、报告 | Node + ImageMagick；新目录；仅独立静态素材，格边不安全就停止 |
| `index-asset-sheet.mjs` | 透明素材图 → 连通块坐标、索引与编号预览 | ImageMagick；识别像素块而非语义对象，名称需确认 |
| `prepare-video-start-frame.mjs` | 素材＋裁切范围 → 不透明首帧、体检说明 | ImageMagick；BBox 双语义及裁切覆盖风险，颜色／清晰度指标是启发式 |
| `run-video-generation.mjs` | 首尾图＋提示词 → 视频、提交标记与日志 | 旧 fal 图生视频入口、ImageMagick、ffprobe；默认预检，确认后可能付费；提交标记不等于服务端成功受理 |
| `analyze-video-cycle.mjs` | 视频或帧 → 推荐周期／窗口／交付帧、指标与预览 | ffmpeg + ImageMagick；会计算推荐帧集，不是语义验收或方向纠正 |
| `detect-residue.mjs` | 帧目录 → 分离残片报告 | ImageMagick；可能漏掉与主体连通的阴影，不替代逐帧检查 |
| `remove-frames-background.mjs` | 已选源帧 → 去背景帧、账本与修复报告 | 旧 fal 去背景入口、ImageMagick，视频输入另需 ffmpeg／ffprobe；真实分支可能逐帧计费与覆盖输出 |
| `prepare-video-frames.mjs` | 视频绿幕抠像或已有 RGBA 帧 → 公共裁切帧、帧表、清单 | ffmpeg／ImageMagick；新目录；本地抠像使用绿色判据，不是任意背景分割 |
| `prepare-frame-sequence.mjs` | 透明帧表＋时序清单 → 统一帧、帧表、元数据与播放器 | ImageMagick；新目录；公共变换、回切像素检查，不理解动作语义 |
| `publish-sequence-sheet.mjs` | 完成包 → 本地资源目录中的 WebP＋元数据 | Node 文件复制；不是远端发布或引擎导入；`replace` 会删除目标子目录再重建，调用方负责备份 |
| `repack-published-size.mjs` | 源帧表／映射＋已有交付 → 尺寸回验、重打包及可选替换 | 调用打包和入库脚本；默认模式也写工作产物／报告，正式替换的备份参数可省略 |
| `produce-animal-batch.mjs` | 动物清单 → 首帧、视频、分析、去背景、打包与本地入库 | 编排上述脚本，可能付费、覆盖；可选复核另需 Python 3／Pillow，不能作为通用队列直接迁入 |

## 运行条件不是“只有 Node”

多数像素脚本没有 npm 依赖，但依赖已安装的 ImageMagick 7；视频分支另需 ffmpeg／ffprobe。源目录没有 `package.json` 声明整体最低 Node 版本，部分文件使用 `import.meta.dirname`、`node:util.parseEnv` 等特性，未来应统一声明并验证运行时。

Sharp 在原主文档中是允许选用的库，不代表这 12 个脚本都需要 Sharp。批处理的可选 Python／Pillow 复核与 Node 脚本是不同依赖，不能漏列，也不能因文档记录而自动安装。

## 状态、续跑与本地写入

| 机制 | 静态核对到的边界 |
| --- | --- |
| 视频提交标记 | 在调用前独占创建，阻止常规重复调用；标记在取 Key 前写入，不能用它证明请求已经发出或已经扣费。`force` 绕过早期判断后仍遇到独占写入，需核对其真实恢复语义 |
| 去背景续跑 | 通常按帧序、源帧号、源图摘要及可解码输出复用；源码兼容缺少源摘要的旧账本，不能声称所有复用都强制核对完整身份 |
| 去背景预检 | 不抽帧或写结果，但复用估算没有重新核对源像素哈希；预估调用数不等于不可超出的费用上限 |
| 本地修复 | `repair-only` 不重新调用模型，但源码仍取 Key、要求 fal 脚本存在；修复直接修改目标帧，不能从已改结果保证恢复原色 |
| 批处理续跑 | 多步骤主要依据某些文件／目录存在就跳过，不是全链路输入哈希幂等校验；警告不一定阻止后续付费或入库 |
| 重打包预检 | 确认参数之前就重渲染旧尺寸；清理固定工作子目录、生成报告。它不是零写入 dry-run，文件路径和覆盖边界需独立审核 |

这里记录缺口是为了后续改造，不提供绕过现有保护的操作步骤。生成候选、逐帧付费、本地正式替换、Git 提交和远端发布分别取得授权。
