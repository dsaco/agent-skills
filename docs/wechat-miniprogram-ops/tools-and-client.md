# 工具边界与客户端排障资料

## 自动化能力：按具体工具版本核实

源记录区分微信开发者工具 CLI 和 `@cloudbase/manager-node`：前者用于环境列表与函数查询／部署，后者覆盖集合、索引和函数配置等管理操作。CLI 当时未提供的操作，不能据此判定整个微信／腾讯云平台都没有 API。

| 事项 | 源记录与使用前检查 |
| --- | --- |
| CLI／HTTP 服务 | 当时依赖 IDE 已启动并开启对应设置；Mac 安装路径不是 Windows 通用路径 |
| 函数部署 | 曾出现信息可读但部署报 `ResourceNotFound.Namespace`；原因未证实，应区分工具通道、账号、地域和环境 |
| manager-node 替代部署 | 旧记录使用 `updateFunctionCode` 与 `installDependency`；当前参数、状态枚举和保留配置语义需查实际版本 |
| 触发器 | IDE 选定云函数目录的目标环境后才出现上传入口；列表响应未含 Triggers 不足以证明没有触发器 |
| ACL／超时／变量 | 分别核对 IDE、CloudBase、SCF API 的当前能力，不能沿用“只能控制台”的绝对结论 |

### CAM 与凭据优先级

源记录涉及 `TENCENT_SECRET_ID`／`TENCENT_SECRET_KEY`，仅保留变量名供将来评估。历史上数据库与 SCF 操作权限分属不同策略；`QcloudTCBFullAccess`、`QcloudSCFFullAccess` 可作为缺权限时的线索，**不作为默认授予全权限的建议**。实施时按动作、资源和用户最小授权。

旧记录发现 shell 已有环境变量可能覆盖 dotenv 文件值。通用结论应是：**明确配置优先级，校验本地来源与目标标识，报告来源／是否就绪而非值**。不能一概强制读取 `.env` 或回显云函数中的密钥来排障。云端环境变量更新还应保留非目标字段，避免整组覆盖；真实凭据不上下文、不入库，Agent 不代用户上传。

### `setup-db.js` 为什么没有迁入

静态阅读确认旧脚本存在：

- 常量形式的示例环境、集合和索引，需要按项目修改；没有通用只读预检或写入前归属断言。
- `.env` 路径按 `__dirname` 指向脚本目录，与“项目根配置”的说明不一致。
- 手写解析只接受有限键格式，且仅在 `process.env` 未设置时赋值，与参考文档强调的“直接文件值优先”冲突。
- 使用有副作用的集合／索引管理调用，未提供事务式迁移或完善回滚保证。

这些是后续重写的输入，不是现在可执行的工具。本资料不安装 SDK、创建集合或复制执行代码。

## miniprogram-automator 旧记录

源记录包含 `cli auto`、WebSocket 连接、`mp.screenshot`、页面节点查询和断连后进程退出等行为。采用前核对工具和库的当前 API。

- 源记录曾将 `page.$$()` 查询不到自定义组件解释为 shadow tree 隔离；实际还可能是查询上下文或 API 用法，不能仅凭空数组判定未渲染或断定所有组件不可查询。
- 查询超时可能与渲染故障有关，也可能是连接、等待条件或选择器问题；**“超时 = 渲染层崩溃”不是充分证据**。
- 使用相同版本、最小复现和对照矩阵，结合逻辑层与渲染层日志；涉及修复效果时补真机验收。
